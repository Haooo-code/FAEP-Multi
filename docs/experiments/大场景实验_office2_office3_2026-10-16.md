# 大场景 A/B/C 对比实验（office2 / office3，2026-10-16）

> 目的：把"单机 / 三机独立 / 三机协同"的对比从 16×30m 的 office 场景迁到更大的
> office2（20×20m）与 office3（19.7×28.8m），检验协同的收益边界。
> 口径：A=单机 FAEP；B=三机独立（无协调，各自覆盖全图）；C=三机协同（协调器 v2.0）。
> 每轮：清理进程 → 重启仿真 → 触发 → 等待完成（B/C 上限 900s，A 上限 600s）→ 归档日志/轨迹。

## 0. 结论速览（**v2.0 扇区分区版**，2026-10-17 更新）

**核心结果：采用"按初始位置划分扇区"的 v2.0 协同后，C 组在三个场景全面优于 B 组
（快 44–50%），且重复覆盖从 90%+ 降到 0–19%。**

| 场景（A/B/C 轮数） | A 单机 (s) | B 三机独立 (s/机) | C 扇区协同 (s/机) | C vs B（时间） | C wall vs B wall |
|---|---|---|---|---|---|
| office 16×30m（5/5/5） | 142.5 ± 8.3 | 167.2 ± 3.6 | **94.0 ± 10.0** | **−43.8%** | 100.4 vs 183.0 s（−45%） |
| office2 20×20m（5/5/5） | 109.3 ± 2.0 | 132.9 ± 6.1 | **66.4 ± 8.3** | **−50.0%** | 73.8 vs 167.6 s（−56%） |
| office3 19.7×28.8m（3/3/3） | 148.3 ± 6.7 | 161.9 ± 3.8 | **90.7 ± 5.9** | **−44.0%** | 97.3 vs 184.0 s（−47%） |

- C 的单机航程从 B 的 154–205m 降到 **59–83m**（总工作量约降 60%），
  重复覆盖（≥2 机共同覆盖占并集）从 B 的 **89–98%** 降到 C 的 **0–19%**。
- C 甚至比单机 A 快 **34–39%**：三机各扫一块，墙钟时间由"最慢扇区"决定。
- 覆盖口径（轨迹 1m 邻域）：C 的并集覆盖 62–83%（B 为 69–87%），差距集中在场景边缘/死角；
  3m 邻域口径下 office2 为 91% vs 96%。**轨迹覆盖是相机覆盖的下界近似**，精确口径建议后续用
  SDF 地图日志核算（见 §5 局限）。

### 0.1 反面对照（重要）：没有分区的 v1 协同反而更慢

同一套协调器不开分区（v1 行为）时：C 比 B 慢 **+21%（office2）/ +29%（office3）**，
重复覆盖 94–98%（与独立几乎相同）。原因见 §3：任务被"最近机贪心"逐个分配、区域散装，
过滤形同虚设，还叠加"释放→重派"空转。**v2 的扇区分区正是针对这个根因的修复。**

## 1. 批跑过程中发现并修复的协调器缺陷（v1.5 → v2.0）

批跑前对 C 模式日志做体检，发现两个真实缺陷并修复（机理分析素材）：

### 缺陷 1：空闲兜底"自由探索"从未触发（死锁）

- 设计：某机长时间无活可干 → 放开单机过滤自由探索（`free_wait_time=20s`）。
- 实际：等待机的任务每 tick 被"释放→重派给最近机"（含它自己），
  而旧逻辑以"名下无任务"计时且在持有任务时**每 tick 复位计时器** → 兜底从未触发
  （office2 C 实测整轮 **0 次**）。
- 修复：改为按"连续处于等待状态（state=2）的时长"计时，连续空闲 20s → 打开自由探索
  （并交还名下任务），此后不再接收区域任务（自主探索直到 HALT）。

### 缺陷 2：等待状态每 0.2s 闪烁，协调器侧计时器永远攒不满

- 无人机端"收到分配消息即清除等待标志"，而分配消息每 tick 都有微变（任务中心平滑更新+
  重派）→ 等待标志以 5Hz 闪烁；协调器看不到"连续空闲"，修复 1 的效果被抵消。
- 修复：无人机端改为**真正规划出可行目标（SUCCEED）才退出等待态**。

### 修复前后对照（office2 C 轮，同场景同参数）

| 指标 | 修复前（旧代码，1 轮可用样本） | 修复后（5 轮） |
|---|---|---|
| 慢机飞行时间（每轮最慢机） | 225.5s | 195.5 ± 36.7s（单轮最慢 263.1s，长尾仍存在） |
| wall | 244s | 210.4 ± 40.6s（165–285s） |
| 等待闪烁日志（resume planning） | 965 次 | 0（该噪声机制被重写） |
| 空闲兜底（free_explore） | 从未触发（死锁） | 条件成立即可触发（本轮等待均 <20s 未触发，属正常） |

> 注：修复前样本少（其余轮次受夜间休眠/进程撞车污染），对照仅供参考；
> 修复的价值主要在代码级结构缺陷的消除（空闲死锁 + 状态闪烁），
> 以及"协同相对独立的差距收窄"：office2 慢机 225.5s → 195.5s（B 参考 158.6 ± 25.6s）。
> **但即便修复后，C 仍比 B 慢约 20%——差距根因见 §3（区域散装），属设计层问题。**

## 3. 根因：区域分配是"散装"的（协同未构成空间分工）

对 C 轮日志的任务-分配记录做空间分析（`check_region_scatter.py`）：

- 122 个任务中心被反复分配 **1322 次**（平均每任务 ~11 次，重派极频繁）；
- 单机分配记录的空间包围盒**几乎覆盖全图**（20×20m 的 [-8.7,9.1]×[-9.3,8.9]），
  且**前 40 次分配就已铺满全图**——任务白名单从未形成"紧凑分区"。

机理：任务按"最近机贪心"逐个分配（任务池含全图前沿），无人机飞到哪里、
哪里的任务就归它 → 分配集天然散装 → 区域过滤形同虚设 → 既无分工、又多了重派空转。

深层约束：FAEP 的无人机只能飞向**自己已探测到**的前沿；把远区任务派给它时它看不到
那里（无目标可飞）。因此"真正的空间分区"需要配套"导航到区域中心再去探索"的能力，
属于 v2 设计（见 §5）。

### 3.1 v2.0 扇区分区：不需要"盲飞"的解法

上面的"可见性耦合"看似要求给无人机加"导航到区域中心"的能力，但换一个划分方式即可绕开：

- **按各机初始位置沿"离散度大的轴"划一维 Voronoi 扇区**（取相邻初始位置的中点作分界）。
  这样每架机**从一开始就站在自己的扇区里**，扇区内的前沿是它沿途自然发现的，
  不需要飞向"看不见的区域"。
- 协调器：任务创建时就归属其所在扇区的无人机，**不再按最近机重派**；等待机的任务不释放
  （分区模式下重派没有意义）；空闲兜底自由探索关闭（空闲 = 本扇区已清完，应等待收尾）。
- 单机：只在自己扇区内选前沿、**只上报本扇区前沿**（快照过滤），前沿集合与任务池一一对应，
  "任务被非 owner 刷新、永不 done"的问题消失。
- 终止：新增"所有机连续 6 秒都不在探索 → 直接收尾"兜底，解决扇区内不可达前沿把任务拖到
  150s 超龄的收尾长尾（实测把单轮 221s 拉回 ~100s）。
- 实现：`FrontierAssignment.msg` 增加 `partition/sector_axis/sector_lo/sector_hi`；
  协调器 `partition_mode` 参数；单机 `inSector()` 过滤与快照过滤。默认关闭，
  不影响 v1 行为与单机基线（A/B 复用了同一二进制）。

## 5. 结论（2026-10-17 更新）

1. **"任务级协同"本身不自动带来收益**：v1（无分区）在三个场景反而比独立慢 21–29%，
   重复覆盖与独立几乎相同（94–98%）。根因 = 任务散装 + 可见性耦合 + 重派空转（§3）。
2. **"扇区分区协同"显著优于独立**：v2.0 三场景单机时间 −44~−50%、wall −45~−56%、
   单机航程 −55~−62%、重复覆盖 0–19%（独立 89–98%）。这是本作品的**核心实验结论**：
   多机协同的收益不来自"有协调器"，而来自**把空间真正分干净**。
3. 协同的工程价值：统一 HALT 终止（全部轮次）、任务池闭环、两个协调器缺陷的发现与修复
   （空闲兜底死锁 + 等待状态闪烁）、以及"全等待即收尾"的终止兜底。
4. 局限与后续（如实写进报告）：
   - 分区边界按初始位置固定，扇区面积不完全均等（取决于部署点）；
   - 覆盖口径是轨迹 1m/3m 邻域近似，差 5pp 集中在场景边缘，需用 SDF 地图日志精算；
   - 尚未做轨迹级避碰（实测最小机间距 8–23cm），v3 方向；
   - 动态任务/通信受限场景下分区需要重平衡策略（未来工作）。
5. 叙事底线（执行方案 §2.5）：所有结论以数据为准；v1 负结果与 v2 正结果都写进报告，
   体现"发现-定位-修复-验证"的完整工程闭环。

## 5b. 2026-10-18 增量实验（v2.1）

> 完整方法、数据与局限见 `plan/等面积与故障注入_2026-10-18.md`。

- **等面积扇区**：按自由区面积（0.2m 障碍膨胀）计算的分界为 office `-2.45/2.25`、
  office2 `-3.60/2.97`、office3 `-4.45/4.55`。office2 面积不均衡度从 Voronoi 的 66.5%
  降到 4.4%，但 6 组交替配对的完成时间差均值 −9.6s、95% 区间跨 0；**不能据此替换 v2.0**。
  交接原值 `-3.6/3.5` 是等宽口径，不是严格等面积。
- **故障注入**：office2 中间机 +41s 被 `kill -9`，3/3 轮检测失联、释放任务、幸存机接管并
  两机统一 HALT；wall 146/173/165s（均值 161.3±11.3s），失联扇区覆盖 77–82%。
  代价是正常轮的约 2.2 倍时间；`recovery_timeout=150s` 为工程兜底，最终 3 轮未触发。
- **收益边界**：三场景 B/C 单机加速 1.78–2.00，与自由区面积/长宽比均非单调；
  3 个场景不足以拟合边界，报告按“观察范围 + 待验证假设”写。
